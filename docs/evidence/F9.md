## Acceptance-by-acceptance evidence

**1. Single file, no hardcoded data, state reload triggers, Refresh flow.**
`scripts/brief_me.html` is one file (HTML+CSS+JS inline); only external
reference is the Google Fonts `<link>`, with `font-family:'IBM Plex Sans',
system-ui, ...` / `'IBM Plex Mono', Consolas, monospace` fallbacks. `init()`
calls `GET /api/state` on load; `doSave()` and the Dismissed-page Restore
handler both call `reloadState()` (`GET /api/state`) on success. The
Refresh button handler does `POST /api/collect` then `reloadState()`, and
toasts `collector_warning` if present. Test: every assertion in the suite
reads dynamically-generated UUIDs/titles from the fixture, which only pass
because the page is rendering live API data, not baked-in content. The
Refresh button itself (and its collector_warning toast) is implemented but
not clicked by this test - `/api/collect` is exercised by F8's own test
suite; see "Pending" below.

**2. Layout (sidebar + main).** DOM: `#sidebar` > `#project-list` +
`#dismissed-entry` + `#answers-panel`; `#main` > `#topbar` (project name,
counts, refresh) + `#content`. Test scene "initial layout" asserts
`#header-counts` ("6 questions / 2 unread reports") and `#dismissed-entry`
text ("Dismissed (1)"), proving both panes are wired to folded state.

**3. QUESTIONS/REPORTS collapsible sections with counts, empty state.**
`#questions-section`/`#reports-section` each keep the count span outside the
collapsible `.section-body` (visible when collapsed); `renderQuestions()` /
`renderReports()` render `<p class="empty-state">...</p>` when a list is
empty. Collapse toggling and the empty-state path are implemented
(`questionsHeaderEl`/`reportsHeaderEl` click handlers) but not exercised by
this test, since the fixture always has items in both sections - the 13
listed test assertions in the acceptance text don't call for this either.

**4. Question card layout (badges, 3 action rows).** `questionCardHTML()`
builds the severity badge (`badge-high` for high), project, age, title,
body, options row + Skip, Other button + persistent input, and the
footer row (resume command / Dismiss link). Test: `badge-multi` on Q2,
`badge-high` on Q3 asserted in the "initial layout" scene; all three rows
are clicked/filled in the "all decisions entered" scene.

**5. Single/multi-choice mutual exclusivity, Other-only shape, no
"Dismiss"/"Skip" literal in `chosen`.** `onQuestionsClick`/`onQuestionsInput`
implement the exclusivity rules; `computePayload()` builds the exact wire
shapes. Test ("answers.jsonl / inbox.jsonl payload shapes"): Q1 (option
only) -> `{chosen:"JSONL"}`, no `free_text` key; Q2 (two options + Other)
-> `chosen` is `{"Alpha","Gamma"}` (order-independent set compare) plus
`free_text`; Q5 (Other only) -> `free_text` only, no `chosen` key.

**6. Other validation (blur + Save-time block).** `onQuestionsBlur` sets
`otherError` when Other is selected and the trimmed text is empty;
`handleSaveClick`'s first check blocks Save entirely (no confirm dialog, no
network call) when any question is in that state. Test: focusing then
blurring Q5's empty Other input shows `.other-error-msg`; clicking Save at
that point is asserted to leave `#confirm-overlay` hidden and to write
nothing to `answers.jsonl` (checked via Q1, which was already answered at
that point and must not have been written yet either).

**7. Dismiss overlay + Skip writes nothing + reopened == pending.** Clicking
Dismiss on Q6 immediately shows "Will be dismissed on save"; the real
`cancelled` status line is only appended by Save's dismiss-processing step.
Test: `q6_statuses` after save has exactly one `cancelled` line, no answer
record; Q3/Q7 (Skip / confirmed-untouched) have zero status lines and zero
answer records anywhere in `inbox.jsonl`/`answers.jsonl`. After Restore, Q6's
card is asserted to not carry the `dismiss-pending` class and its Dismiss
button is visible again, i.e. it behaves like an ordinary pending question.

**8. Answers panel (unsaved count, per-project rows, dispatch/watch,
button label states, footer note).** `updateAnswersPanel()` implements all
of this from a single `computePayload()`. Test: selecting Q1 alone flips the
Save button to "Save 1 answers" and `#answers-projects` to contain
"demo-project: 1 new"; the watch checkbox is asserted disabled by default,
enabled once "Dispatch after save" is checked, and forced back to
disabled+unchecked when dispatch is unchecked. The "Dispatch N projects" /
"Save N and dispatch" label branches and the footer note text are
implemented (same `updateAnswersPanel()` function, same `if/else` ladder as
the tested branches) but not separately asserted - F9's acceptance-13 test
list does not call for dispatch-state assertions (that surface is F8's).

**9. Save flow: confirm dialog for untouched questions, POST /api/answer,
dispatch project union, result toast.** `handleSaveClick()` computes the
untouched list from all loaded questions (not just the current project
filter) and opens `#confirm-overlay` before proceeding. Test: with Q7 left
untouched, clicking Save shows the dialog containing Q7's title; "Skip them
and save" proceeds, and the save round-trip is confirmed by Q1/Q6 dropping
out of the QUESTIONS list while Q3/Q7 remain. The dispatch `projects` union
(`answerProjects ∪ unconsumed_projects`, sorted) is implemented in
`doSave()` but not exercised here since "Dispatch after save" was left
unchecked for the whole save (see item 8's note); `showSaveResultToast()`
implements the saved/dismissed/dispatched/log_paths/dispatch_error toast
text.

**10. Report card collapse/expand/read-once + resume command.** Covered
directly: expanding R1 (has `session_id`) shows `.report-full`, the resume
command text, hides its unread dot, and is confirmed via `wait_for` to have
appended exactly one `status: read` line; collapsing and re-expanding is
confirmed (after a 0.3s settle) to still be exactly one line. R2 (no
`session_id`) is confirmed to render no `.resume-cmd` element at all.

**11. Dismissed page (filters, match count, Restore, sidebar-return).**
Test: entering the Dismissed view shows "2 / 2" (Q4 pre-cancelled + Q6);
typing part of Q6's title narrows it to "1 / 2"; clearing it restores
"2 / 2". Clicking Q6's Restore posts `/api/reopen`, switches back to the
inbox view automatically, and Q6 reappears in QUESTIONS. A separate scene
re-enters the Dismissed view and clicks the "All projects" sidebar item,
asserting it switches back to the inbox view. The project-dropdown filter
(`#dismissed-project-filter`) is implemented with the same filtering logic
as the tested keyword search, but not separately asserted: the fixture only
uses one project, so filtering by project name vs. "All projects" would not
produce an observably different list.

**12. Accessibility (cursor pointer, focus-visible, 36px+ buttons, 150ms
transitions, no silent API failures).** `:focus-visible{outline:2px solid
var(--accent)}` is global; `cursor:pointer` is set on all interactive
classes (`.btn`, `.opt-btn`, `.side-item`, `.dismiss-link`, `.resume-cmd`,
`.section-header`, `.report-summary-row`, `.dispatch-row`); `min-height` is
40px on `.btn` and 36px on the smaller controls; `--transition: 150ms ease`
is applied to hover/expand rules. Every `apiGet`/`apiPost` call site
(`init`, Refresh, Save, Restore, mark-as-read) has a `.catch()` that calls
`toast(..., 'error')`. These are CSS/structural properties verified by
reading the stylesheet and JS, not by a Playwright visual assertion -
consistent with F9 acceptance item 13's own test list, which does not ask
for CSS-property assertions either.

**13. The Playwright test itself.** `tests/test_brief_me_html.py`,
`tests/_stub_api.py` - this file's "Command and output" section above is the
evidence; `git status --porcelain` before commit shows only the four files
in F9's `touches` list changed.
